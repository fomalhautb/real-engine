# 基准、参考与验收协议

状态：验收设计，2026-10-14。本文所有数值为初始目标或测试配置建议；仓库尚未因本文产生任何性能结论。实测结果应另存，并附提交、资产与环境记录。

## 功能矩阵与验收

建立机器可读的能力矩阵，每行包含：ID、所属子系统、P0/P1/P2、场景、输入规模、正确性参考、画质门槛、性能预算、兼容组合、支持状态和证据位置。验收范围和门槛在测试前冻结；修改必须保留版本与原因，不能测试后缩减范围。

单项必须同时满足功能、画质和预算，才记为通过。几何、世界空间光照、材质、形变及跨系统组合分别列出通过、未通过和未支持的用例。阶段完成须通过该阶段全部 P0、对应的质量和性能预算、兼容组合与全局稳定性门槛；P1/P2 的实际支持状态和限制逐项披露，不用汇总分数掩盖关键缺失。

跨系统用例单独设置必过门槛：几何通过不能抵消动态角色在反射中缺失；材质球正确不能抵消阴影覆盖错误。新增能力必须补充受影响组合的用例。

F01–F05 与几何、光照、材质及形变用例同属阶段 2 的 P0 组合门槛，各项均分别报告通过、未通过和未支持；F06 随阶段 4 的高级透明开放。冻结机器可读矩阵时记录范围版本，不用任何一项新能力替代其他用例的验收。

## 三种参考

1. **几何参考**：原始 LOD0、关闭遮挡剔除，使用同一变形状态，比较轮廓、深度、法线和覆盖。
2. **光学参考**：同几何、材质、灯光的高采样离线路径追踪。确认已收敛，并披露不受参考渲染器支持的特性。
3. **产品参考**：固定 UE 5.8 的具体补丁版本、项目设置、Nanite/Lumen 路径、Substrate GBuffer 模式和质量档。记录版本与配置文件哈希；没有对应实测时不得写“与 UE 持平”。

曝光、单位、相机、白平衡、色调映射、环境贴图与纹理处理固定。分别保存线性 HDR、最终图像、深度、法线、直接光、间接漫反射和间接镜面。UE 的实时结果也是近似解，不能兼任所有物理正确性真值。

F01 的介质透射和积分另用独立解析解，例如均匀消光下 `T(d) = exp(-sigma_t * d)`；F02–F04 在相同范围和参数下使用高采样积分参考，并另存完整介质光学离线参考以显示单次散射近似的视觉差异。被明确排除的多重散射不记为数值 bug，也不能隐瞒其画面影响。

公开场景可使用 Cornell Box、Intel Sponza、Blender Classroom 和有适当权限的高面数扫描资产；UE City Sample 只作其许可范围内的 UE 端系统参考。记录资产版本、哈希、转换步骤与许可证，不把不同资产转换造成的差异归因于渲染器。

## 自动 LOD 分簇演示验收

G01/G02/G03 在正常材质视图之外，必须提供实际 cluster ID 的稳定分块颜色、LOD 层级和页驻留/祖先回退视图。分别保存拉近、拉远、绕行、快速转头及触发缺页的固定轨迹视频；使用同一轨迹和质量参数，支持隐藏诊断面板生成演示素材。

- 颜色来自实际绘制簇的稳定资产/primitive/cluster 身份。固定相机且无场景变化时，颜色不因帧号或可见列表排序闪变；实例的着色身份策略须一致且公开。
- 画面分块变化与实际选择的簇 ID、三角形数和 LOD 层级一致。对选定像素/簇可检查对应元数据；不能只以统计面板变化证明 LOD 在运行。
- 在面板中显示实际可见簇数、绘制三角形数、屏幕误差参数、驻留/请求页及帧时间。CPU 参考选择和 GPU 实际选择分别标明，不能把 CPU 演示误称 GPU 驱动。
- 冻结 LOD 和逐帧推进用于检查边界；正常材质和调试颜色只改变诊断输出，不能改变 Mask 覆盖、形变、阴影或光照查询几何。开启调试视图的额外成本单独记录。
- 缺页时明确标出祖先回退；对应正常材质视图仍无破洞。最终大场景录屏同时包含正常观感和分簇视图，记录构建指纹与视角轨迹。

当前 `/geometry.html` 已有驻留 GPU LOD 的材质、实际簇颜色和层级视图，以及暂停/逐帧和固定轨迹控制。尚无页面流送/祖先回退或大型真实资产录屏，本节的完整要求仍未通过；小型演示截图只作为当前实现的可视证据。

## 阶段 2 大型场景与视觉交付

这是阶段 2 后期的必交付项，当前尚未加载、转换或验收以下候选。至少覆盖高质量室内与室外环境，其中一个整理为可连续游走的完整演示场景；同时保留小型数值回归，防止美术复杂度掩盖算法错误。

| 候选 | 选择目的 | 接入前审计 |
| --- | --- | --- |
| Intel 新版 Sponza＋扩展包 | 近景建筑、彩色反弹光、遮挡、植被和动画角色同场 | glTF 材质、法线/贴图保真；角色转换；未支持光学不能静默忽略 |
| ORCA Amazon Lumberyard Bistro | 连续街区和室内，复杂遮挡、粗糙反射、室内外光照过渡 | FBX 转换、相机/曝光统一；保留几何、材质与原始归属 |
| Intel Jungle Ruins | 高密度室外植被、微小几何、流送和风动压力 | Blender/USD 转换；分别统计独特数据与实例展开量，不以标题三角形数证明驻留能力 |

Intel 发布了上述 Sponza、植被、角色扩展和 Jungle Ruins，并提供相应格式和归属许可说明：[Intel Samples Library](https://www.intel.com/content/www/us/en/developer/topic-technology/graphics-research/samples.html)。Bistro 发布页列出约 105 万室内三角形、283 万室外三角形，格式为 FBX/Falcor，许可为 CC-BY 4.0：[ORCA Bistro](https://developer.nvidia.com/orca/amazon-lumberyard-bistro)。这些是发布方信息，尚非本引擎导入后的测量；每份实际下载仍须保存版本、许可证和哈希。

验收冻结以下镜头与动作：近距离石材/金属/布料/叶片；走廊进入庭院；彩墙出屏但继续照亮墙面；反射中出现离屏动画角色和移动刚体；开关灯与开门；快速转头、瞬移和多次回访已淘汰区域；室内窗洞/门洞光柱被移动角色遮挡；室外薄雾中的风动植被和局部灯光。植被、角色、动态物体和多种材质需同时启用，分别报告各数量及动态更新预算。两个环境均保存相同曝光的开雾/关雾画面，以及移动灯光、局部雾团增删和镜中雾的时间序列；不能靠浓雾遮住几何流送缺陷。

视觉交付采用相同相机、曝光、材质与光源的高采样参考，并保存原始/LOD 几何对照、线性 HDR、最终图和时间序列。评估近景轮廓、纹理/法线细节、间接色彩、反射完整性、阴影接触、闪烁与拖影；正常速度的连续录屏不可缺失。最终画面须经过用户视觉验收，数值/性能门槛也须通过，不把主观“次世代”标签当作已验证事实。

规模验收继续使用 G02/G03：独特驻留格式数据至少为几何池的 4 倍；重复实例压力另列。冻结目标 GPU、1080p 输出与内部分辨率、画质档、采样和重建设置，执行预热、重复采样、p50/p95/p99 和 30 分钟稳定性协议。任何降级、动态规模裁剪或尚未支持的材质均列入结果，不通过降低内容复杂度重定义最终目标。

## 环境与测量协议

基础场景已提供 `npm run benchmark` 入口，命令见 README，当前实现与短测证据见 [implementation.md](implementation.md#基准运行器与首轮证据)。它尚未覆盖下述全部目标协议：rAF 是回调间隔，GPU 时间是已接入 pass 的稀疏样本，没有显示器实际呈现时间；场景更新也尚未细分物理与动画。不能用这组基础数据替代阶段 2 的大场景验收。

记录操作系统、GPU/驱动、浏览器准确版本、WebGPU features/limits、功耗设置、代码提交、构建配置、资产哈希、随机种子、相机轨迹及事件时间线。发布测量使用正常浏览器配置；实验 flags 独立报告。

默认每个序列预热 300 帧、测量 1800 帧、重复 3–5 次。慢收敛 GI 可以延长预热，但须统一并披露；冷启动和首次遇到材质另测，不混入稳定运行数据。输出 p50/p95/p99、超预算帧比例及时间序列，不只报告平均 FPS。

分开记录 CPU 更新、物理、编码/提交，GPU 各 pass 与整帧，实际呈现帧间隔、网络/解码/上传等待。CPU/GPU 可重叠，不能简单相加。可选 `timestamp-query` 不可用时明确缺项，不能用提交耗时代替 GPU 时间。采样读回须异步且低干扰，报告其开销。

内存记录应用分配账本、各池峰值、驻留页面、解码暂存及缓存数量；不能声称这些等于驱动真实显存。网络至少区分不限速、50 Mbps/40 ms、10 Mbps/80 ms，以及冷/热缓存。

F01–F05 同样固定并报告相机、米制单位、消光/散射/发光参数、相函数、密度资产/噪声种子、网格 XYZ、近远距离及深度分布、历史权重和失效策略。压力扫描可从每格 4/8/12 像素、48/64/96 个深度层，以及 0/4/16/64 个局部体积和局部灯开始；重叠上限、有阴影灯数及反射采样另列。这些是实验配置，不要求所有组合全部驻留，也不能把缩小视距或变粗网格后的耗时与原画质直接比较。

介质 pass 的计时区分共享阴影/光照与增量工作，避免重复记账或漏算新增查询；timestamp 不可用时保留缺项。保存散射 `L_fog`、透射率 `T`、密度/光照调试切片、关闭历史的参考序列、最终图及开关对照。反射沿对应光路采样介质，不能复用主视图累计结果；高级透明未实现前明确报告 F06 未支持。

## 初始验收目标

以下指标在阶段 1/风险实验后校准；未指定硬件与场景之前，不能视为产品承诺。

| 项目 | 建议门槛或检查 |
| --- | --- |
| 基础输出 | 桌面目标机 1080p 输出，明确内部渲染分辨率；30 fps 基础档、60 fps 优化档 |
| 帧时间 | 基础档 p95 约 33.3 ms，p99 ≤ 50 ms；同时报告超预算比例 |
| 几何 | 1 内部像素作为初始 LOD 误差参数；实际测量轮廓与深度，不以参数代替结果 |
| 几何正确性 | 固定轨迹无新增裂缝、错误剔除和缺页破洞 |
| 真正流送 | 驻留格式折算后的独特数据量 ≥ 几何池 4 倍，持续淘汰仍可游走 |
| GI 稳态 | 标准 ROI 归一化误差初始目标 10–15%；黑暗区单独测绝对漏光 |
| GI 离屏 | 漫反射受光面在贡献物体出屏后的稳态亮度变化 ≤ 10% |
| 介质数值 | F01 透射率绝对误差 ≤ 0.001；有信号的散射/发光 ROI 归一化误差 ≤ 1%；零密度返回 `T=1`、`L_fog=0`（无独立发光时），无 NaN/Inf |
| 介质画面 | F02/F04 的散射与透射分开测量，线性 HDR ROI 初始归一化误差目标 10–15%；薄墙和近黑区域另测绝对漏光 |
| 动态响应 | 普通灯光变化 T90 ≤ 0.5 秒；T90 为完成最终亮度变化的 90% |
| 介质动态 | 直接灯光开关/移动 T90 初始目标 ≤ 100 ms；GI 引起的变化仍按 ≤ 0.5 秒；保存残影面积与亮度曲线，短闪光不能只验稳定终态 |
| 历史恢复 | 已驻留场景瞬移后约 1 秒恢复稳定照明；网络缺页恢复另测 |
| 时域稳定 | 固定镜头 120 帧，非近黑区域亮度波动初始目标 ≤ 3% |
| 介质时域 | 固定种子、冻结动画的 120 帧亮度波动目标 ≤ 3%；瞬移/resize 当帧拒绝无效历史，已驻留内容约 1 秒内重新稳定 |
| 材质更新 | 数值参数更新不新增 pipeline；静态特性新增变体可计数、预热 |
| 介质资源 | 桌面基础档 1080p，增量 GPU 工作 p95 暂以 ≤ 2 ms、应用持有资源峰值 ≤ 64 MiB 为原型预算；包含注入、照明、历史、积分、合成及新增阴影/查询成本，按目标硬件校准 |
| 联合画面 | 开/关雾均通过几何和材质验收；开启介质、GI、反射与动态对象后仍满足整帧预算和 30 分钟稳定性 |
| 长时运行 | 30 分钟无崩溃、验证错误、失效句柄及持续无界内存增长 |

误差公式与 ROI 必须冻结。建议线性 HDR 的归一化 MAE 使用 `mean(abs(test-reference)) / max(mean(abs(reference)), epsilon)`，epsilon 与曝光一起记录；近黑区域改用绝对误差和亮斑面积。FLIP 等感知指标作补充，不让全图平均掩盖裂缝、漏光和小面积反射缺失。动态序列另测亮度波动、响应曲线及残影区域，不能用静态截图验收运动质量。

## 结果与回归

每次新增可见成果都在对话中展示实际运行截图或视频；能说明变化时使用固定相机、相同曝光的开关或前后对照，并注明提交、功能范围与限制。用户使用本机期间优先从远程浏览器回归取得画面，不为截图启动本机 GPU 负载。截图说明外观，不能替代数值、性能、时序和稳定性验收。

每次结果包含环境清单、统计 JSON/CSV、关键帧、差异图、性能轨迹与失败说明。对已声明支持的组合，错误不得静默降级；输出能力诊断并判为未通过。性能回归需重复确认噪声和环境，再比较同配置结果。只有新变更、新失败或未解决风险才扩大测试范围，避免无目的重复测量。
