# 第一阶段实现状态

更新日期：2026-10-14。当前正在实现阶段 1.2；完整阶段 1 和阶段 2 的目标保持不变，逐项状态见 [phase-1-2-status.md](phase-1-2-status.md)。尚未完成 Nanite 类虚拟几何或 Lumen 类光照。

## 已实现的运行路径

原生 WebGPU 初始化、能力检查、可诊断错误与设备丢失报告；TypeScript 运行时、WGSL 着色器、Vite 构建。运行场景只使用仓库生成的测试模型，不依赖下载或未授权的美术资产。

场景输入由通用 contracts 定义，不依赖 Three.js 或 Babylon.js。有界顺序形变图支持多个 Morph、蒙皮和解析 wave 程序位移，编译为融合 WGSL，并按结构复用 pipeline。角色使用两个 Morph 加蒙皮；树木使用蒙皮加 wave。姿态来源与算子执行分离，没有角色/植被专属执行分支。支持至多 32 个算子、1024 根刚性骨骼、32 个 Morph、128 个标量；实际批次容量仍受 WebGPU 资源限制。每顶点保持四个骨骼影响；不声称支持任意算子或任意 DAG。

每个变化的批次执行一次 Compute，输出当前世界位置、法线和上一渲染帧位置，供主视图和太阳阴影共用。Morph 包含位置与法线增量；wave 使用解析雅可比修正法线。动态包围盒在 CPU 按算子传播保守边界，不遍历运行时顶点，也不做 GPU 几何读回；蒙皮边界取各骨骼变换后的并集，目前偏宽松。

SceneStore 使用 index/generation 句柄和按影响分类的资源版本，显式提交增删、变换、形变和历史失效事件。DemoScene 的模拟数据与 renderBatches 分离；commitFrame 仅应用增量事件。渲染历史使用事件携带的 historyVersion，重置和尺寸变化拒绝旧历史。已提交的实例对象在变化时替换：相同数据静止一帧、使前帧追上当前帧后，可复用形变结果并跳过整批上传。直接提供 mutable 输入的调用方仍逐帧更新。当前仍按批次更新；不是完整的稀疏 GPU 更新器。

实际 deformation、shadow、surface pass 通过 Render Graph 执行，编译时检查读写依赖、未初始化读取、纹理同 pass 读写和环路，记录资源使用区间。当前 GPU 分配仍由 Renderer 持有，没有自动资源别名分配器。

表面使用不透明金属度/粗糙度 PBR、单方向光、1024 平方阴影图与比较采样。额外输出 rg16float 运动向量。环境补光是常量近似，不是世界空间 GI。地面网格仅用于测试场景的空间参照。

Rapier 以独立适配器提供盒子刚体和地面碰撞、最近命中射线查询（实体过滤、位置、法线、世界单位距离）和球形重叠查询。查询读取当前物理碰撞状态，不读取相机 LOD 或插值显示几何。正常步进后使用 Rapier World 的广相加速；创建/瞬移/删除后尚未步进时，使用 O(碰撞体数量) 的直接查询保证结果立即有效，不以偷偷步进改变模拟状态。模拟固定 60 Hz，显示读取插值姿态；卡顿追赶最多 5 步并记录丢弃时间。场景支持暂停、重置、添加和删除刚体。演示角色和树木尚无碰撞体。

运行诊断记录应用持有的 GPU buffer/texture 字节、实例和顶点数、CPU 编码提交时间，以及可用时的 GPU timestamp。该账本不包含驱动、WASM、浏览器和交换链内部占用；CPU 提交时间也不是整帧耗时。GPU 查询使用低频异步读回；几何读回仅在显式诊断时执行。

## 当前能力边界

| 能力 | 当前状态 |
| --- | --- |
| 统一形变执行 | 有界顺序算子编译；多 Morph、可变骨骼数蒙皮、wave；骨骼暂限刚性矩阵 |
| 法线 | Morph 目标法线增量、蒙皮混合、wave 雅可比、实例逆转置；尚无通用切线重建 |
| 渲染调度 | 依赖编译和实际执行；当前三个 pass，尚无资源自动分配/别名 |
| 材质 | 常量颜色、金属度、粗糙度；无纹理、Masked、透明、专用 BSDF 和材质 DSL |
| 资源 | 固定容量批次、初始化分配、尺寸变化时重建目标；无资产流送或自动预算管理 |
| 几何 | 常规索引绘制与实例化；无簇层级、LOD、遮挡剔除、虚拟几何 |
| 光照 | 直接光与阴影；无世界空间查询、GI 或反射 |
| 物理 | 地面、盒子刚体、最近命中射线与球形重叠查询；无角色控制器、ragdoll、布料或破坏 |
| 平台 | WebGPU 必需；初始化失败明确报错，设备丢失报告后停止帧循环，恢复需要重新加载 |
| 性能 | 基础可测量切片；未完成大量动态物体、30 分钟稳定性及真实硬件性能验收 |

场景动画仍在 CPU 生成矩阵，变化的批次仍上传全部活动实例。SceneStore 的防御性拷贝和骨骼验证也有 CPU 成本；虽然已去除逐实例线性查找和静止批次重复变形，但尚未达到大量动态对象的性能目标。后续需要连续数据布局、细粒度上传、Worker 与 GPU 姿态生成的测量。

Rapier compat 将 WASM 内嵌在 JavaScript，初始 bundle 较大。模块分包和 WASM 单独加载是后续加载性能任务，不能通过提高构建警告阈值当作解决。

## 验证入口

- npm run check：TypeScript、Vitest 数学/几何/物理/场景测试、生产构建。
- npm run test:browser：Chromium 软件适配器上的 WebGPU 编译、渲染、GPU 与 CPU 形变比较、重置、尺寸变化、实例操作与错误路径。
- 运行页的 GPU 验证按钮：显式读回每批第一实例的全部顶点，对照 CPU 当前/前帧位置及法线，误差门槛为 0.0002；还要求当前顶点全部位于保守包围盒内。
- 运行页导出 JSON：记录本次环境与诊断；不等同完整 benchmark 报告。

软件适配器验证功能正确性，不证明目标 GPU 帧率或兼容所有浏览器。截图用于检查场景可见性；它不能替代后续的阴影、BRDF、运动向量和 GI 数值验收。

阶段 1.1 的历史结果：2026-10-14 的 19 项 Vitest、TypeScript、构建以及 Chrome 154 软件/硬件两项浏览器测试通过。

阶段 1.2 的本地结果：65 项 Vitest、TypeScript 与构建通过。Chrome 154.0.8037.99 的三项浏览器测试覆盖可见场景、缓存收敛、resize、物理查询、初始化失败以及六骨骼/双 Morph/wave 的真实 GPU 执行。基础场景检查四批首实例共 460 个顶点；额外测试每帧检查四实例共 96 个顶点，改变算子顺序并重排实例，按独立提交快照核对 entityId 对应的当前/前帧位置。正常硬件配置在 RTX 3070 Laptop GPU 上通过；这些是功能结果，不是固定场景性能基准。

浏览器配置通过 PLAYWRIGHT_CHANNEL 选择已安装通道，通过 PLAYWRIGHT_GPU=hardware 禁用软件测试 flags。默认 Chromium for Testing 下载与系统浏览器是独立安装，测试不修改用户的日常浏览器配置。

Linux 软件 GPU 的 CI 使用 Xvfb、启用 GPU 合成和 Vulkan SwiftShader，避免适配器初始化成功但 canvas 首次获取纹理时设备丢失。该配置依据 [luma.gl 的复现实验](https://github.com/visgl/luma.gl/issues/2874)；必须由本仓库的实际渲染测试验证，不能把获得 adapter 当作渲染通过。

CI 将失败时的运行状态直接输出到日志。截图附件上传属于可选诊断；账户存储配额不足时只影响附件上传，不能令通过的测试失败，也不能令失败的测试变为通过。
