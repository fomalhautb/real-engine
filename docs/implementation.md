## 已实现的运行路径

原生 WebGPU 初始化、能力检查、可诊断错误与设备丢失报告；TypeScript 运行时、WGSL 着色器、Vite 构建。运行场景使用程序网格、仓库内原创 OBJ 卡片和固定版本的 Khronos glTF 参考资产；运行时仅请求本地托管的文件。第三方来源、许可证与哈希见 [assets.md](assets.md)。

场景输入由通用 contracts 定义，不依赖 Three.js 或 Babylon.js。有界顺序形变图支持多个 Morph、蒙皮和解析 wave 程序位移，编译为融合 WGSL，并按结构复用 pipeline。角色使用两个 Morph 加蒙皮；树木使用蒙皮加 wave。姿态来源与算子执行分离，没有角色/植被专属执行分支。支持至多 32 个算子、1024 根骨骼、32 个 Morph、128 个标量；实际批次容量仍受 WebGPU 资源限制。每顶点保持四个骨骼影响；不声称支持任意算子或任意 DAG。

蒙皮默认刚性模式；显式 `normalMode: 'affine'` 支持非均匀缩放、剪切和反射骨骼，以混合线性变换的逆转置处理法线。这是在顶点固定权重下的 LBS 法线近似，不是包含权重空间梯度的精确微分。各骨骼须非奇异；混合结果接近奇异时使用有界、有限的混合法线回退，CPU 与 WGSL 一致。导入的 glTF 蒙皮使用此模式；网格实例整体反射变换尚未实现绕序修正，会明确报错。

每个变化的批次执行一次 Compute，输出当前世界位置、法线和上一渲染帧位置，供主视图和太阳阴影共用。Morph 包含位置与法线增量；wave 使用解析雅可比修正法线。动态包围盒在 CPU 按算子传播保守边界，不遍历运行时顶点，也不做 GPU 几何读回；蒙皮边界取各骨骼变换后的并集，目前偏宽松。

SceneStore 使用 index/generation 句柄和按影响分类的资源版本，显式提交增删、变换、形变和历史失效事件。DemoScene 的模拟数据与 renderBatches 分离；commitFrame 仅应用增量事件。渲染历史使用事件携带的 historyVersion，重置和尺寸变化拒绝旧历史。已提交的实例对象在变化时替换：相同数据静止一帧、使前帧追上当前帧后，可复用形变结果。SceneStore 在提交边界隔离输入，包括更新回调保留的草稿和插入的外部嵌套对象；drainChanges 复用内部已提交值，对外 getter 仍返回防御性副本。

CPU 打包和实例/骨骼/标量上传按变化的槽位执行，相邻槽位合并；超过 16 个分散区间时，上传从首个到末个变化槽位的一个连续区间，限制 queue.writeBuffer 调用数量。数量变化才更新批次参数；未变化槽位保留已有 GPU 输入。移动后的下一静止帧仍更新 previous=current；重排按槽位重写而历史按实体/generation 查找，删除后清理历史。同批实体 ID 必须唯一，ID/generation 为 uint32。mutable 输入每帧重打包全部活动槽位，从 mutable 切回 committed 也强制更新一次。变化批次的 GPU 形变和可选 BVH refit 仍整批执行，尚未实现按脏实例的 GPU dispatch 或逐帧上传字节预算。未启用 GI/LOD 的完全静止场景只上传 256 字节相机/光照参数；可选模块各自的参数上传另计。

实际 deformation、shadow、surface、resolve pass 通过 Render Graph 执行，编译时检查读写依赖、未初始化读取、纹理同 pass 读写和环路，记录资源使用区间。开启世界查询时还执行 BVH refit。当前 GPU 分配仍由 Renderer 持有，没有自动资源别名分配器。

材质由有界、无副作用的表达式图定义，支持常量、vec4 参数、实例颜色/金属度/粗糙度、RGBA8 纹理、加法、乘法与插值。编译上限为 128 个节点、深度 32、16 个 vec4 参数和 4 个纹理槽。当前覆盖金属度/粗糙度 PBR 与 Unlit、Opaque 与 Masked、单面与双面；同一材质定义产生主视图和阴影 pass 的覆盖函数，Masked 丢弃在两条路径一致。材质 shader/pipeline 按静态图缓存，默认至多 128 个变体；达到上限时仅按最近使用顺序淘汰未被引用且不在编译的变体。`setMaterial(batchName, binding)` 异步准备并原子替换，多个并发请求以最后一次为准；失败保留旧材质。`setMaterialParameters` 更新运行时数据，不重新编译 shader。

纹理资产支持 sRGB 或线性 RGBA8，CPU 生成完整 mip 链；sRGB 的 RGB 在线性光下滤波并量化回 RGBA8，alpha 在线性值下滤波。四个纹理槽各自使用独立采样器，可设置重复/镜像/夹边、最近/线性过滤和 LOD 范围；非法配置在分配材质资源前报错。Masked 阈值保持非负值，超过 1 时丢弃全部覆盖，符合 glTF 语义。当前使用面积平均 mip，不包含 alpha 覆盖率保持；主视图和阴影的纹理足迹不同，细小遮罩的边缘可能因过滤出现差异，共享覆盖公式并不保证跨分辨率逐像素相同。默认材质图像预算为 256 MiB，统计实际引用图像的全部 mip，排除 1×1 后备纹理；原子材质替换期间新旧图像必须同时容纳在预算中。`Renderer.create` 可配置纹理字节预算和材质变体上限。这是当前材质资源限制，不是逐帧上传预算、纹理流送或设备真实显存占用量。

OBJ 导入器接受位置、法线、UV、正/负索引及三角形或平面凸多边形；按对象、组和材质段保留网格，顶点按不同 UV/法线引用拆分，缺失法线按原始面生成平面法线。凹多边形、非平面面和未支持的指令会明确报错；`s` 平滑组被忽略并给出警告。材质库名称仅记录，不解析 MTL 或纹理文件。演示场景使用原创竖直 OBJ 卡片、带 alpha 镂空的 Unlit/Masked 双面材质，以及重复 UV 的棋盘格纹理地面；两者经过通用几何和材质路径。

表面使用单方向太阳光和接收面导数感知 PCF；`setSun` 可更新方向与线性 RGB 辐亮度。`RendererOptions.sunShadow` 配置 256–8192 的二次幂分辨率、包含接收面及离屏投影物的世界包围盒、米制 padding 与纹理字节预算；未配置时保留 1024 平方、50 米覆盖的旧投影。聚焦投影覆盖包围盒八角点，并把光空间中心对齐到阴影纹素，预留对齐和 float32 的边界余量。`setSunShadowFocus` 在保留纹理分辨率时更新范围，不重分配纹理；非法变更保留原投影。当前仍为一张正交阴影图，范围之外不会自动获得精细阴影，尚无级联或虚拟阴影页。额外输出 rg16float 运动向量。未配置 GI 的原有场景仍使用常量环境补光；显式配置 `diffuseGi` 后由下述世界空间查询替代。

GI 房间显式采用 2048 平方、16 MiB 阴影图，世界范围 `[-3.5,-0.25,-4]`–`[3.5,4,4]`。默认太阳方向下，光空间覆盖约 10.318 米，每纹素约 5.04 毫米，旧配置为 48.83 毫米。固定相机的原生 NVIDIA 截图显示地板和后墙台阶减轻；独立斜边射线/平面参考的 628 个有效采样，平均可见性绝对误差由 0.19606 降到 0.0003715，明暗控制和近接触遮挡保留，释放后账本为零。这是该斜边及房间范围的证据，不表示大世界阴影已验收。

`RendererOptions.antiAliasing` 和 `setAntiAliasing` 支持 `none`（接口默认）与 `fxaa`（GI 演示开启）。FXAA 在原 resolve pass 中对色调映射后的 sRGB 值判断边缘并手动插值，HDR、深度和运动附件保持原值，不增加纹理或 pass。实现参考 [NVIDIA FXAA 说明](https://developer.download.nvidia.com/assets/gamedev/files/sdk/11/FXAA_WhitePaper.pdf) 和 [FXAA 3.11 原始讲义](https://www.iryoku.com/aacourse/downloads/09-FXAA-3.11-in-15-Slides.pdf)，采用自定义的固定四步双向边界搜索、符号拒绝与 subpixel 混合；不是全部官方 preset 的逐字移植。每像素最多 45 次有界 HDR 纹素读取，低对比区域提前返回原像素；所有邻点访问显式夹边。原生 GPU 蓝白斜边相对四倍宽高参考的 295 个边界像素误差由 80.32 降到 41.36（每像素 RGB 绝对误差之和，8-bit 单位），平坦区域逐字节一致，HDR 不变，模式切换及 resize 可重复。它不恢复细小几何、不消除时间闪烁，也不能代替后续时域重建。

`invalidateHistory()` 显式拒绝相机和对象历史，尺寸变化也使用相同入口。诊断用 `probeVelocity` 最多读取 1024 个精确像素，返回当前减前帧的 UV 位移（右为正 X、下为正 Y），无逐帧 GPU 读回。实际附件测试使用独立投影计算，覆盖相机、刚体、蒙皮、Morph、停止运动、单实体重置、镜头切换、resize、遮罩洞与背景；half-float 读回误差门槛为 0.0001。

## 离线几何构建与页面

`buildGeometryHierarchy` 使用固定的 meshoptimizer 1.3.0 JS/WASM，把一个静态 Opaque primitive 构建为簇 DAG：LOD0 保留全部原始三角形身份，各层按空间顺序分组、简化并重新分簇。每簇默认至多 64 顶点、128 三角形，每组默认 4 簇；原始顶点属性保留，简化只改变索引。不同材质 primitive 不合并。按位置识别 UV/法线分裂顶点，锁住组间与已终止区域边界，再独立核对简化前后的有向几何边界；无法有效简化的组保留为终止根。当前使用 Morton 空间分组，尚无邻接图分区优化。

层级同时记录紧包围盒、继承的 LOD 包围盒、来源三角形、组关系与累计近似误差。误差使用原始局部空间单位，是简化器的近似指标而非严格几何距离上界；正误差下限保证阈值为零时精确选择 LOD0。`selectGeometryCut` 是按视点、投影尺度、近裁面与像素误差选择完整切分的 CPU 参考，没有视锥/遮挡剔除、驻留判断或 GPU 执行。原始输入缓冲不修改；未引用顶点不改变几何范围和归一化精度。每个稀疏组先压紧局部顶点再调用 WASM，避免小组反复复制整份源网格。

输入默认限制 100 万顶点、100 万三角形；全部层级累计默认至多 300 万三角形、65,536 簇和 65,536 组，层数默认 16。布局、非有限数、退化三角形、索引与预算均检查。此构建切片只接受静态 Opaque；Masked 或非空形变图会明确拒绝，仍使用现有全细节渲染路径。形变和遮罩的简化误差、轮廓与跨 pass 一致性是后续必交付项，不能靠本次静态限制缩减通用引擎目标。

`encodeGeometryPages` / `decodeGeometryPage` 提供版本化独立页面，以 meshoptimizer 无损压缩保存原始 80 字节顶点记录、可选 UV/切线、源顶点身份及簇局部三角形。页面含格式/数量/长度和完整性校验；解码在按声明分配前验证长度、数量及预算，并核对索引、有限数与填充。默认每页解码载荷 64 KiB、累计编码加解码载荷 256 MiB。这些是格式载荷预算，不包含 JS 对象、WASM 暂存、原始解码块和返回数组同时存活的进程峰值。页面按稳定簇顺序打包；根页面映射可能同时带入其他簇，尚未优化根集驻留成本。

`npm run build:geometry -- --input path.obj --output artifacts/geometry/example --coverage opaque` 提供可重复 OBJ 构建入口，源文件上限 32 MiB。调用方显式声明 Opaque；OBJ 的材质库只记录名称，不自动转换或判断覆盖。工具保留 primitive 名称/材质名、源 SHA-256、构建参数、簇/根页面映射和页面 SHA-256，先写入自有暂存目录，再发布到不存在的输出目录。`hierarchy.json` 含重复的簇索引，明确作为离线审计元数据；不是可直接全部载入生产运行时的驻留清单。

Windows 下目录发布偶发 `EPERM`：工具保留向同一父目录的私有副本发布，再仅对最后一次原子目录重命名作最多八次、总计 6.35 秒的有界重试；每次重查目标不存在，失败清理自身暂存目录。本轮一次完整 `npm run check` 通过，但间歇文件锁是否彻底消除仍需后续重复运行验证；不会覆盖既有输出。

CPU 回归以带属性接缝的曲面网格核对 LOD0 完整性、真实减面、组边界、DAG 单调误差/边界、多个误差阈值下的无孔洞/重复覆盖，以及页面往返、损坏输入、预算与构建可重复性。此证据只覆盖小型正确性用例，未进行本机 GPU 或大型资产压测。运行时选簇接入见下节；压缩页面尚未接入流送/祖先回退，不能把离线产物视作完整虚拟几何。

本轮最新本地 `npm run check` 通过：244 项 CPU 单元测试（31 个文件）、TypeScript 和生产构建。浏览器功能与硬件计时证据按下文各自的实际运行范围记录。

## 驻留 GPU LOD 与可视化

可选 `SceneBatch.geometryLod` 接受 `buildGeometryHierarchy` 的产物，批次 `mesh` 必须引用 `hierarchy.source`。当前只接受空形变图和空 Morph 目标，实例可通过原有模型矩阵变换；Opaque 材质启用 LOD，切换成 Masked 时显式走原来的全细节路径，恢复 Opaque 后重新启用。阴影和世界查询仍读取完整源几何及共享当前/前帧状态，调试颜色不改 Material IR、覆盖或查询返回值。动态蒙皮/Morph 简化、阴影/查询各自的几何 LOD 与误差控制仍未实现。

`packGeometryLod` 在上传前验证布局、索引、LOD0 来源覆盖、DAG 双向关系、层级和误差单调、继承边界、组边界与根集。GPU 每帧扫描有界的簇/实例对，按世界空间保守包围盒和变换尺度上界计算屏幕误差；选择完整层级切分后执行视锥剔除。选中簇把索引写入同一 GPU 缓冲，原子计数生成 `drawIndexedIndirect` 参数，每批一次主视图绘制，不逐簇发出 CPU draw。单独的完成 pass 检查容量溢出；溢出时禁止该批间接绘制并在诊断中报告，避免越界或把残缺几何当正确结果。

这是全部驻留的硬件光栅基线：所有层级及源顶点常驻，默认至多 128 MiB LOD GPU 资源、262,144 个簇/实例对、每批 256 实例；还受设备 storage buffer 大小与 dispatch 限制。输出索引容量按源三角形数乘实例容量分配。当前没有层级遍历加速、遮挡剔除、流送、缺页祖先回退或微三角形软件光栅；形变输出仍按完整源网格计算，不能据此宣称达到大量动态对象或超内存场景性能目标。

`setGeometryLod` 提供 `maxErrorPixels`（0 为 LOD0）、`frustumCulling`、`frozen` 和 `debug`。冻结只固定选择相机，实际画面相机和实例姿态仍可变化；不是冻结整个世界。`debug` 可选 `material`、`clusters`、`levels`：簇颜色由 primitive 身份与簇 ID 稳定生成，使用实际索引对应的簇身份；原子压紧顺序改变不会换色。只有主视图最终颜色被覆盖，深度、速度、选簇及材质语义保持原路径。

`probeGeometryLod` 是显式、异步的 GPU 计数/选簇诊断，返回提交帧号、实际索引/三角形数、簇 ID/层级/实例及溢出状态，不参与生产 LOD 决策。旧 `stats.triangles` 仍表示源网格实例展开量，不能当实际选择量。GPU LOD 选择与完成 pass 的时间戳进入 `gpuMs.geometryLod`、基准 CSV 和总和；CPU 提交统计不等于整帧时间。查询禁用或不存在该模块时相应耗时为零。

`/geometry.html` 用同一份 5,120 三角形的波纹雕塑展示三个变换实例和普通地面/基座，提供材质/簇/层级视图、误差、视锥、冻结视点、固定轨迹、暂停逐帧、隐藏 UI 和诊断导出。实际数量只统计雕塑批次，面板最多每 500 ms 异步读取并显示采样帧。CPU 用例验证模型绕序、真实减面和合法打包；浏览器用例将 GPU 选簇对照 CPU、核对恢复及调试色的实际 HDR 像素，保存真实运行截图。该演示不代表高模资产、大场景、最终画质或硬件性能已验收。

## 世界空间查询基础

`Renderer.create(canvas, batches, { worldQueries: {} })` 显式启用软件 BVH 查询。禁用时不分配查询缓存，也不执行 refit。CPU 对不可变网格建立确定性、中位数划分的先序 BVH；每叶默认至多四个三角形。GPU 从光栅与阴影共享的当前世界空间形变缓冲计算叶边界，再按深度从下到上更新内部节点，每层独立 compute pass，避免依赖跨工作组屏障。静止、已缓存的批次跳过 refit。此处是可验证的基线实现，不是 GPU 层级构建、TLAS 或针对大规模动态场景优化后的查询器。

`traceRays(rays, { textureLod: 0 })` 返回最近命中的批次/实体/generation/三角形、距离、当前与前帧位置、法线、UV、PBR/Unlit 参数和拓扑/历史版本。输入方向归一化，距离按世界单位，`tMin`/`tMax` 为闭区间；可以忽略指定实体及 generation。几何来自最近一次 `render` 提交，与相机可见范围无关；返回的 `frame` 标识这份几何。材质程序和参数使用查询开始时已原子发布的状态，返回独立 `materialRevision`，无需为了更换材质重复形变。两者构成显式版本对，不承诺所有数据都是同一历史帧。实例增删、变换及形变变化需先提交 `render`。

查询复用同一 Material IR、图像、采样器、参数与 coverage 函数，Masked 不覆盖时继续遍历；双面与背面剔除遵循当前材质。纹理使用调用方给出的显式 mip LOD，尚无射线锥/微分，不能声称所有距离下与光栅滤波逐像素相同。Unlit 保留非负 HDR 颜色。当前不支持任意拓扑就地改写：替换网格、顶点/索引/UV 流引用、容量或 queryIdentity 会明确报错，需重新创建 renderer。数组内容依不可变资产合约使用，不每帧全量哈希。

默认限制为 1,024 条射线、每网格 65,536 三角形、每批次 256 个实例、总查询分配 128 MiB，批次数硬上限 256。单条遍历上限默认 262,144 个工作单位；一次提交默认至多 16,777,216 个工作单位，平均分配到射线并与单条上限取小值。工作单位包括实例检查、BVH 节点与三角形测试，跨全部批次累计；超预算显式返回 overflow，诊断 API 抛错，不以不完整命中或 miss 冒充正确结果。此上限限制算法工作量，不保证所有硬件都满足帧预算。

GPU 模块提供驻留的 rays/hits 缓冲与编码入口，供后续光照直接消费；CPU `traceRays` 仅按需读回有界命中记录，不读取整份几何。同一编码器可按顺序多次查询；不可变、对齐的 uniform 槽位允许各次使用不同的 ray count 与 LOD 参数，相同参数复用槽位。默认每 encoder 最多 8 组，硬上限 32 组，超出明确报 `WORLD_QUERY_ENCODER_PARAMETER_BUDGET`。同一 encoder 内仍须保持同一帧、材质、批次数量与拓扑快照；跨 encoder 查询仍按编码、提交、再编码的顺序执行。外部 GPU 射线生产者必须遵守有效输入合约并检查 overflow。当前遍历各实例根边界为线性扫描，三角形部分使用无栈 BVH；材质仍按批次分别 dispatch。新增缓冲均计入应用 GPU 账本并随 renderer 释放。BVH refit 在首末 compute pass 之间计时，静止批次复用缓存；新增元数据/层级参数上传计入当前帧上传统计。额外显式射线查询不在普通 render 帧计时范围内。

提交 `63f2bd8` 已通过本地及远程 TypeScript、176 项 CPU 单元测试、生产构建，以及 [远程 Linux 软件 GPU 的 14 项浏览器回归](https://github.com/fomalhautb/real-engine/actions/runs/38509599939)。GPU 查询覆盖离屏静态/刚体、独立蒙皮＋Morph、重排/删除/generation 复用、Mask 洞口、双面、前帧位置、多层 refit、闭区间命中、Unlit HDR 材质即时修改和预算错误；无 GPU 验证错误，释放后账本归零。这是该提交的功能证据，未测查询吞吐。后续本地硬件与基础压力场景的 30 分钟运行另见本文末节；此前被中止的运行不计为通过。

## 世界空间漫反射 GI

`RendererOptions.diffuseGi` 配置固定世界空间探针网格（origin/spacing/counts）、每探针射线数、查询距离、法线偏移、天空辐亮度、可选 `multiBounce` 与可见性低置信度阈值。`multiBounce` 默认 `false` 且须严格为布尔值；`visibilityWeightThreshold` 默认 0.2、范围为 `[0,1]`，设为 0 关闭额外的低置信度曲线。必须同时配置足够 `maxRays` 的 `worldQueries`；开启发光面采样时 `maxTraceParameterSetsPerEncoder` 至少为 2。每帧先复用当前共享形变的 BVH，生成固定 Fibonacci 球面射线并查询材质，再从命中点向太阳查询遮挡，最后累积九项入射辐亮度 SH 系数，以及 8×8 八面体方向深度图的距离一、二阶矩。方向深度图每格用确定性的归一化余弦 32 次幂权重捕获。射线与命中留在 GPU，不读回几何或可见列表；镜头外物体仍参与照明。多轮 trace 在同一 encoder 中依次执行，独立参数槽位保留不同查询的 count/LOD。

命中着色使用同一 Material IR、纹理、Opaque/Masked 覆盖和共享形变。每帧的基础捕获为一次漫反射表面反弹：PBR 使用漫反射率乘太阳辐亮度及世界查询遮挡，发光项直接参与，Unlit 使用 baseColor+emissive 作为出射辐亮度。开启 `multiBounce` 时，两份 SH 探针场交替读写，本帧命中点通过与表面相同的可见性感知插值读取上一已完成场，再把间接漫反射辐亮度加入本帧捕获；采样按探针记录的最大 RGB 辐亮度约束反馈，避免无界增亮。这是跨帧反弹，不是同帧递归追踪或时域平均。金属不产生漫反射反弹，不捕获镜面光路。天空仅在射线未命中时贡献。太阳射线也受 `maxDistance` 限制，超过该距离的遮挡不计入本次捕获。

表面按法线对 SH 做余弦卷积得到 irradiance，使用八邻点三线性权重、法线方向权重及八面体四纹素双线性距离矩插值，再乘接收材质的漫反射率；反馈采样复用同一个 GPU 插值 helper。基础置信度为 `facing² × visibility³`；低于阈值时再乘 `(confidence / threshold)²`，然后与三线性权重相乘。最终按权重和归一化，分母下限 `1e-12` 保持均匀辐照场在弱置信度位置不被整体压暗。阈值经 `gi.sky.w` uniform 传给两条路径，不改变材质程序。GI 不修改生产材质、阴影覆盖或 LOD 调试身份。探针范围向各轴延伸半格；范围外返回零间接光。`setDiffuseGiEnabled(false)` 去掉间接光并停止探针更新，不恢复旧常量补光，便于公平截图对照。`setDiffuseGiMultiBounce(boolean)` 切换反馈模式，`invalidateDiffuseGiHistory()` 显式失效历史；启停模式、太阳或材质编辑、实体身份/generation/historyVersion 或实例数量变化时，在下一 render 帧拒绝旧反馈。连续模型变换与蒙皮运动查询当帧几何，允许上一已完成探针场逐帧收敛；相机变化不使世界空间 GI 历史失效。诊断公开模式、失效原因、最近历史帧及失效后的更新次数。

可选 `DiffuseGiOptions.emissiveSamplesPerProbe`（默认 0，整数 0–64）配合不可变的 `SceneBatch.emissiveSampling: 'triangle-area'`，主动采样该批次的实际发光几何。样本从共享的当前形变三角形生成，按三角形面积、实例/三角形选择概率、发光面余弦和距离平方转换成立体角权重；世界查询验证目标三角形/实体/generation/距离，并求当前材质、Mask 和双面覆盖。普通方向射线只排除这些批次的发光项，仍捕获 PBR 的太阳反射和 GI 反馈；面积样本只补发光，避免重复计光。同方向的反射和发光最大值采用加法保守上限，两个捕获分量各限 65504，合并上限至多 131008，最终表面 HDR 仍限 65504。没有独立灯光颜色副本、CPU 几何读回或按对象类别复制管线。

这是有界的基础实现：最多 512 探针、每探针 16–256 条方向射线、单轮至多 65,536 条；默认每帧两轮查询，开启已注册发光面采样时增加第三轮。实际面积样本数 `发光批次数 × 探针数 × 每批次样本数` 不得超过方向射线总数；超出在注册时明确报错。第三轮只查询实际面积样本的活跃前缀；内洞清空，尾部 inactive 样本省略。GI 容量仍按最大配置保留；关闭发光面采样时其工作计数为零。当前演示第三轮由原来的 27,648 条填充查询降为 6,912 条，三轮合计 62,208 条。GI 独立预算默认 32 MiB，包含参数、主命中备份、两份 1,184 字节/探针记录、诊断读回、`64 × raysPerProbe × 4` 字节捕获权重，以及开启时每射线 48 字节面积元数据和发光批次的索引/身份/参数；共享查询内存另计。任一捕获工作量或数值超限会使整颗探针无效，读回分别报告 `primaryOverflows`、`shadowOverflows`、`emissiveOverflows`。面积计数占距离记录首格原保留的 w，不扩大探针结构。`gpuMs.diffuseGi` 包含所有生成、查询、复制及积分，进入基准总计/CSV；BVH refit 单列。

当前没有时域平均、单点局部收敛缓存、增量/优先级更新、自动放置或重定位、探针流送及镜面反射。网格由调用方放在自由空间；没有自动检测实体内部探针。8×8 距离矩与低阶 SH 仍是粗近似，近场接触细节、薄墙残余漏光、边界截断及动态采样变化需更广验收。未选择面积采样的发光体仍可能漏采；面积采样为固定有限样本，近距离大三角形、很多实例和遮挡边缘仍有方差，不含自动发现/重要性排序、光源树或 MIS。每帧全量刷新尚未达到大场景目标。不能把它称为完整 Lumen、完整 DDGI 或阶段 2 完成。可见性感知插值参考 [JCGT 的 DDGI 论文](https://jcgt.org/published/0008/02/01/)；这里没有复用其完整算法。

## 线性 HDR、输出与光照基础

表面材质现在先输出线性的 `rgba16float` 场景颜色。原有距离混色已移除；雾、GI 和反射应在这个线性空间合成，最后由独立 resolve pass 应用曝光、现有 filmic 拟合曲线和准确的 sRGB 传递函数。`setExposure(ev)` 支持 −16 至 +16 档，只改变输出曝光，不改材质程序、场景辐亮度或运动历史。当前没有自动曝光、局部曝光、色彩分级、TAA 或 HDR 显示器输出；场景内部 HDR 与显示设备 HDR 是不同能力。

场景附件在写入时限制到 half-float 的非负有限范围 `[0, 65504]`。这是一项公开的存储上限，超出上限的材质/光照会截断；尚未实现预曝光来扩大可用范围。全分辨率深度、运动向量与 HDR 颜色共占 16 字节/像素，resize 对称释放和重建。`probeHdr` 仅按需读取最多 1024 个像素的线性颜色。resolve 和可选 BVH refit 已进入 GPU 时间、基准 CSV、分位统计和总和；不包含浏览器合成/扫描输出或额外诊断查询。

`participating-media.ts` 是均匀介质的 CPU 解析参考：米制消光、RGB 散射反照率、每米发光和有界 HG 各向异性，支持 Beer–Lambert 透射率、零消光稳定极限、分段前后合成及 `L_medium + T * L_surface`。七项数值测试覆盖真空、纯发光、微小光学厚度、分段等价和相函数归一化。它尚未注入 GPU 网格，也不代表 F01–F05 或完整体积雾已经通过。

提交 `2454e22` 已通过本地及远程 TypeScript、184 项单元测试和生产构建，以及 [远程 Linux 软件 GPU 的 16 项浏览器回归](https://github.com/fomalhautb/real-engine/actions/runs/38510988726)。HDR 附件在曝光前后及 resize 后均读到 `[5, 0.75, 0.125, 1]`；EV 0 的 canvas RGB 为 `[0.99216, 0.87451, 0.45098]`，EV −2 为 `[0.92941, 0.56471, 0.15686]`，符合 filmic＋sRGB 解析预期和 8-bit 量化。曝光不重编材质或清除对象运动历史；resize 的账本增量为 16 字节/像素。

设备丢失回归用测试侧 `GPUDevice.destroy()` 注入故障，验证错误报告、停止增加帧号、查询拒绝以及幂等释放归零；同时验证普通 `dispose()` 不误报丢失。丢失期间已发出的时间戳读回可能同时报告 mapAsync 中止，这也是预期诊断。此用例不模拟驱动崩溃，也不代表自动恢复或跨厂商设备丢失路径已验收；当前恢复仍需重建应用或重新加载。

## glTF 与动画资产

`loadGltf` 读取 glTF 2.0 JSON 或 GLB v2，支持相对 URI、外部 buffer、data URI、GLB BIN、PNG/JPEG 图像。二进制读取检查 component 对齐、步长、矩阵列填充、normalized 整数和 sparse accessor。默认下载累计上限 128 MiB，解码后 RGBA8 图像累计上限 256 MiB；图像尺寸由浏览器解码得知后，在创建 canvas/读取像素前检查剩余预算并关闭 bitmap。该预算不能阻止浏览器自身解码阶段的一次暂存分配。未被纹理引用的图像不解码；所有图像源元数据仍校验。嵌入图像必须声明 PNG/JPEG MIME，范围不得越过 buffer 声明长度。加载支持 AbortSignal；转换和动画采样目前仍在主线程。

三角网格支持位置/法线/UV0、四权重蒙皮、多 Morph 和 inverse bind matrices。缺失法线时按 glTF 规范展开三角形生成平面法线，同时重映射权重、UV 和 Morph；已有法线时缺失的目标法线增量为零。切线流保留供后续材质使用；缺失基础法线时按规范忽略切线。当前材质不消费切线，无法线贴图。材质映射基础颜色、金属度 B/粗糙度 G、发光纹理/因子、sRGB/线性角色、Unlit、Mask、双面和 glTF 采样器。透明混合、法线/AO 贴图、额外 UV/权重集、压缩网格和未支持的材质扩展明确报错，不静默删除效果。

动画支持节点 TRS 和 Morph 权重的 STEP、LINEAR、CUBICSPLINE；旋转 LINEAR 用四元数球面插值，三次插值按 glTF 时间间隔处理切线并归一化旋转。层级、节点矩阵、通道唯一性、时间顺序和数据类型均验证。默认/硬上限为 4096 节点、65,536 通道和累计 1600 万个动画标量（含时间）；动画解码前计入每个重复引用的通道，可配置更低预算。几何默认上限为输出 100 万顶点、300 万索引。

`GltfSceneInstance` 选择一个场景，将每个节点/primitive 的姿态发布到统一 SceneBatch，Morph 在蒙皮前执行；骨骼矩阵为 `inverse(meshWorld) * jointWorld * inverseBind`，与实例世界矩阵组合。共享资产的各实例可以独立采样动画，Renderer 按实体保存前帧；跳播/瞬移可显式使历史失效。资产和像素在导入后按不可变输入使用；实例状态变化需重新发布。无动画片段的资产复用已提交姿态，显式历史失效时重新发布；时间和片段索引仍验证。有动画时省略片段索引表示播放第 0 段，不会误用静态缓存。当前每个 primitive 单独成批，动画采样仍分配 CPU 数组，尚无跨节点自动批处理、动画混合或大型角色群性能保证。

SimpleSkin 和 AnimatedMorphCube 已与原演示同场运行。测试用它们验证独立时间线、实际运动顶点、两目标 Morph、前帧状态和法线；它们不是最终规模与画质资产。实现依据 [Khronos glTF 2.0 规范](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html)。阶段 2 后期的完整高质量场景另按 [大型场景验收](benchmarks.md#阶段-2-大型场景与视觉交付)交付。

Rapier 以独立适配器提供盒子刚体和地面碰撞、最近命中射线查询（实体过滤、位置、法线、世界单位距离）和球形重叠查询。查询读取当前物理碰撞状态，不读取相机 LOD 或插值显示几何。正常步进后使用 Rapier World 的广相加速；创建/瞬移/删除后尚未步进时，使用 O(碰撞体数量) 的直接查询保证结果立即有效，不以偷偷步进改变模拟状态。模拟固定 60 Hz，显示读取插值姿态；卡顿追赶最多 5 步并记录丢弃时间。场景支持暂停、重置、添加和删除刚体。演示角色和树木尚无碰撞体。

运行诊断记录应用持有的 GPU buffer/texture 字节、实例和顶点数、CPU 编码提交时间，以及可用时的 GPU timestamp。该账本不包含驱动、WASM、浏览器和交换链内部占用；CPU 提交时间也不是整帧耗时。GPU 查询使用低频异步读回；几何读回仅在显式诊断时执行。深度诊断也只在显式调用时读取：[WebGPU 的 `copyTextureToBuffer`](https://www.w3.org/TR/webgpu/#dom-gpucommandencoder-copytexturetobuffer) 对深度格式要求拷贝完整纹理子资源，因此当前实现会读取整个主视图和阴影深度图，成本随分辨率增长，不属于逐帧渲染路径。

场景动画仍在 CPU 生成矩阵。CPU 打包/上传已支持变化槽位和有限区间，GPU 形变及 BVH refit 仍以批次为粒度；世界查询身份元数据和层级参数也仍随脏批次整批上传。SceneStore 的防御性拷贝和骨骼验证仍有 CPU 成本，尚未达到大量动态对象的性能目标。后续需要连续数据布局、Worker、GPU 姿态生成与按脏实例调度的测量；减少上传字节不等于已经证明整帧提速。

Rapier compat 将 WASM 内嵌在 JavaScript，初始 bundle 较大。模块分包和 WASM 单独加载是后续加载性能任务，不能通过提高构建警告阈值当作解决。

## 基准运行器与首轮证据

`npm run benchmark` 构建并复制独立生产版本，通过本地 HTTP 与单独浏览器上下文执行，导出 JSON、CSV 和最终画面。固定随机种子、逐帧相机/太阳轨迹、300 帧默认预热和 3 次默认重复；可选真实秒数而不是帧数。每渲染一帧推进 1/60 秒模拟时间，故模拟时间与墙钟时间明确分离。`measuredDurationMs` 使用与秒数停止条件相同的起点；统计中的 `summary.elapsedMs` 是首末样本之间的跨度，不用于判定 30 分钟。

压力模式每 1800 帧循环增删 16 个刚体、两个已预热材质间替换、1920×1080 与 1440×810 切换、场景重置和镜头切换。每个完整循环检查基础资源恢复为 6 个刚体、7 个材质绑定、2 张共享图像及初始 GPU 账本；重置也复位下一次生成位置，避免后续循环的刚体生成高度不断累积。结束时验证全部活动实例的形变/法线/边界，读回在计时窗口之外；释放后应用 GPU 账本必须为零。

统计记录 rAF 间隔、场景更新、压力事件、CPU 编码提交、上传字节、工作量和 GPU 账本；timestamp 结果携带原始帧号，缺失样本留空，不把旧结果重复算作新帧。当前 GPU 合计包含 deformation/shadow/surface/resolve 和启用时的 BVH refit、GPU LOD 与 diffuse GI，不含浏览器合成与呈现；旧的三项输入仍可读取，新增项按零兼容。逐帧遥测使用按需分配的有界 Float64 块，上限 100 万帧；遥测本身会增加 JS 内存。脚本每 15 秒通过 CDP 观察 JS 堆与页面对象数，未强制 GC，也尚未单独量化观察开销。场景更新目前合并物理、动画与帧提交，不提供各项独立耗时。

环境清单记录 OS/CPU、可查询到的 GPU 驱动、浏览器版本/flags、WebGPU features/limits、代码提交与 dirty 状态、源码逐文件及聚合 SHA-256。构建前后源码哈希不一致时失败；完成的构建副本另记录逐文件及聚合哈希，因此实际运行内容可追溯。秒数运行另设请求时长加 10 分钟的故障超时；帧数运行有显式有限超时，超时只判失败，不充当稳定性通过。浏览器隐藏、页面错误、验证错误和资源漂移均拒绝结果。
