# 项目路线与交付门槛

状态：计划基线，2026-10-14；阶段完成以测试和交付物为准。本文中的人力、工期与性能数字都是估算或目标，不是实测结果。

## 项目范围

目标是 AI-native、代码优先的浏览器 WebGPU 通用引擎，覆盖角色、大量动态物体、高细节环境与动态照明。核心模块可组合，游戏代码处理玩法和项目特定逻辑。没有编辑器产品线；几何虚拟化、世界空间 GI/反射、材质与统一形变是核心研发线，而非彼此独立的 demo。

“80%”表示冻结的目标用例矩阵之加权覆盖率，不表示复刻 Unreal 源码、全部视觉细节或任意场景的 80% 性能。几何、光照、材质、形变分别计分，不能用某项超额表现抵消另一项关键缺失。所有 P0 必须通过，再计算 P1/P2 的覆盖率；画质、性能、稳定性和组合兼容分别设门槛。详见 [benchmarks.md](benchmarks.md)。

## 阶段 1：建立可运行的统一基础

交付目标是一个能反复运行、检查和测量的端到端切片，而不是先画出大量接口。基础场景同时包含静态物体、刚体、蒙皮＋Morph 对象、多个材质实例、动态灯光、阴影及碰撞。

| 工作包 | 具体交付 | 出口条件 |
| --- | --- | --- |
| 浏览器运行时 | WebGPU 初始化、能力检查、尺寸变化、设备错误处理、帧循环 | 正常配置浏览器运行；错误可诊断 |
| Scene 与变更 | 稳定句柄/generation、帧快照、增量变更、资源版本 | 创建、删除、变换和换材质无失效引用 |
| 统一形变 | 代码描述算子图；刚体、蒙皮、Morph；当前/前帧结果与边界 | 同一结果供主视图和阴影复用；动画状态不串用 |
| 材质与直接光 | PBR/Unlit、实例参数、纹理、双面、Opaque/Masked；基础阴影 | 数值更新不产生无意义 pipeline；覆盖与变形一致 |
| 物理适配器 | 固定步、刚体/碰撞体、基础查询、变换同步 | 物理和显示时间关系明确，交互示例稳定 |
| 资源与诊断 | 分配账本、pass 标记、性能采集、资源释放 | 30 分钟稳定运行；能解释主要耗时和内存 |
| 测试入口 | 固定轨迹/种子、截图和数值检查、浏览器 smoke test | 可重复执行，不依赖人工点击完整流程 |

阶段 1 的共享蒙皮与 Morph 是后续虚拟几何和追踪的基础。最小实现可以只支持一部分算子，但不能在接口上把角色和植被永久拆成不同形变体系。基础阴影不要求立即实现 Virtual Shadow Maps；先用可验证方案建立多 pass 一致性。

当前开工点为 **1.1：基础设施与最小切片**：原生 WebGPU、TypeScript/WGSL、Vite、Vitest 与 Rapier 适配器；程序化人形和树使用同一蒙皮/Morph 求值路径；保存当前/前帧几何；实现金属粗糙度 PBR、太阳光阴影、固定步刚体示例、结构化诊断与 GPU 读回正确性检查。完整算子图编译器、完整材质 IR、GI 与反射不是第一轮提交的完成承诺。1.2 再扩展接口覆盖和阶段 1 出口测试，避免把基础设施搭建误报为阶段完成。

应优先完成的顺序：运行时与观测 → Scene/资源 → PBR 与阴影 → 共享形变与前帧状态 → 物理同步 → 联合测试。并行工作只能在输入输出契约明确后开展。首次提交的原型不自动等于阶段 1 完成。

## 阶段 2：虚拟几何与世界空间光照

几何侧建立离线资产构建、簇层级、误差与边界约束、GPU LOD/剔除、间接绘制、压缩分页、请求合并与淘汰。先用硬件光栅建立正确性基线，再根据微三角形压力测试选择软件光栅优化。

光照侧先完成可验证的世界空间查询：静态、刚体及共享形变状态均能被离屏射线查询。比较软件 BVH 与距离场的吞吐、更新成本和误差；以数据选择主路径，允许它们承担不同任务，避免同时生产化多套尚无证据的方案。

随后接入探针/辐射缓存、遮挡感知插值、动态漫反射 GI、跨帧反弹、粗糙反射和受控光滑反射。屏幕追踪仅作细节补充。材质、灯光、形变和页面变化必须驱动正确的缓存更新。

出口条件：独特资产数据超过驻留池仍能持续游走；缺页不破洞；快速转头无持续误剔除；彩墙离屏仍贡献 GI；动态角色和刚体能在离屏反射中出现；开关灯、开门及移动对象达到约定响应门槛。存在的近似必须按质量档公开。

## 阶段 3：规模、性能与生产稳定性

把独立功能组合进代表性通用场景，扫描实例数、动态比例、蒙皮顶点数、材质变体、灯光数、透明覆盖与独特资产量。优化必须针对测得的瓶颈：GPU 调度、材质分桶、形变复用、加速结构增量更新、流送、纹理占用和历史缓存。

交付包括稳定资源预算、异步 pipeline 预热、内容质量档、结构化诊断、跨 GPU 厂商回归、网络压力与冷启动测量。达到整体帧预算才算完成，不能只展示某个 pass 很快。禁止通过隐藏被测动态对象、缩小追踪范围却不披露等方式改善成绩。

出口条件：约定硬件与场景达到帧时间、画质、内存和 30 分钟稳定性门槛；全部 P0 组合通过；能从一条命令生成基准结果和对比报告。

## 阶段 4：高级算子、光学与拓扑

扩展程序形变、模拟约束、曲线、拓扑变化和更高效代理更新；完善皮肤散射、发丝、眼睛、布料、透射、水、有限多层 BSDF 及高级材质位移。并非把角色相关基础功能拖到最后：基础角色在阶段 1，动态角色离屏照明在阶段 2；本阶段扩展复杂度与质量上限。

每个新能力必须同时交付语义、调度/资源成本、跨系统用例和降级机制。拓扑变化需有身份映射或历史失效策略；高级透明不得只在主视图看起来正确。完整 Groom、多层锐利反射、动态细分和特殊光学分别估算，不被“支持一个材质节点”掩盖成本。

可移植性不是阶段 4 才开始的工作。功能探测、厂商差异、可选特性回退和设备丢失处理从阶段 1 持续执行；本阶段扩大设备和系统覆盖。

## 团队与时间估算

建议以 10–12 人核心团队规划：几何/资产 2 人，光照/查询 2 人，材质/编译 2 人，形变/物理 1–2 人，运行时/资源/平台 1–2 人，测试/性能基础设施 1 人；技术负责人统筹跨模块契约，可与上述职责重叠。这是职责划分，不是把模块封闭交接。

在已有相关经验、资产准备充分和目标桌面硬件明确的前提下，**3–6 个月争取一个可验收的整合切片，12–18 个月争取范围明确的 v1**。这不是承诺，不能把无限团队规模视为无限并行度。第一个月完成风险实验后，应根据软件追踪、共享形变和流送测量修订工期。

## 决策与风险管理

每个阶段保留设计决策记录：问题、候选方案、测量、选择及复审条件。最早验证的风险是动态世界查询成本、材质跨路径一致性、几何简化裂缝、浏览器资源限制和冷启动 pipeline 编译。遇到瓶颈应先明确内容规模、误差和更新预算，再选择结构性优化。

若目标硬件上世界空间动态查询已耗尽帧预算，不能以仅屏幕空间效果代替后宣称完成；应公开调整目标硬件、质量档、动态规模或重新设计表示。阶段完成必须有代码、可运行场景、自动结果与限制清单四项证据。
